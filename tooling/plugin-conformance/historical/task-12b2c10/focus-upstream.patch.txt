    Copy and Find in the focused viewer: Edit → Copy answered, and Ctrl/Cmd+F puts the cursor in the search field
    
    Copies reach a viewer only while focus is inside it, Edit → Copy included. The last commit gave the headless `SelectionClipboard` a `target` in all four frameworks (Angular: the `epdfSelectionClipboard` directive, shaped like `epdfCommandShortcuts`) and listened on that element, which missed a copy from the browser's Edit menu: with no DOM selection (the viewer draws its own) it goes to the page's body. `wireSelectionClipboard` now listens on the document and acts only while focus is inside its target, for the copy and for Ctrl/Cmd+C, before the text-field rule. `containsFocus` follows a slotted element to its slot, so your components slotted into the viewer count, as they do for its keys.
    
    Panels ask for the cursor through state. `shell.open(id, { focus: true })` and `toggle(id, { focus: true })` raise the surface's `focusRequest`, also when it is open already; closing clears it, and snapshots leave it out. A command's `panel` takes `focus`. The element that should get the cursor says so: `useSurfaceFocus(id, ref, { select })` in React and Vue, the `surfaceFocus` attachment in Svelte, the `epdfSurfaceFocus` directive in Angular, all following `@embedpdf/web`'s `createSurfaceFocusFollower` (a new request moves the cursor in, and so does mounting while one is up, as a lazy panel does). React's hook runs after the frames, so a sheet records its opener and gives focus back to the button on close. `moveFocusInto` moves focus into a container unless it's there already; the focus trap and the viewer's overlay use it, so a field that took the cursor as its panel opened keeps it.
    
    In the viewer, Ctrl/Cmd+F is Find (`search:find`, brought with the search panel): search with the cursor in its field and the text selected, never closing it. A command can run its shortcut from text fields (`shortcutInTextFields`; `matchStroke` takes `inTextField`), and Find does, so pressing it again in the search field, or in any field in the viewer, selects the search text instead of opening the browser's find. The Search button puts the cursor in the field too; a plain `open('search')` leaves it where it is. "Find" is in all 13 languages, and the shortcuts sheet lists it under Viewing.
    
    Docs: Panels (focus, and opening one with the cursor in it), Buttons & commands (`search:find`, `shortcutInTextFields`, copying in the focused viewer), and the headless Panels (putting the cursor in a panel, with a snippet per framework), Commands (`shortcutInTextFields`) and Text selection (`target` in each framework) pages.
    
    Tests: a browser test for copying with two viewers on a page, each with text selected: Ctrl/Cmd+C copies from the focused one only, Edit → Copy at the body is answered by the focused one, and the page's own selected paragraph is left to the page; each case fails without its change (the last commit's listener on the viewer fails Edit → Copy; a page-wide listener without the focus check fails the key and the paragraph). A browser test for search: Ctrl/Cmd+F puts the cursor in the field and typing searches; pressed again from the field it keeps search open, selects the text and keeps the browser's find from opening; the Search button puts the cursor there; a plain open leaves it; at 800 px, where search opens over the pages, the field has focus, not the close button. Unit tests for the follower, `moveFocusInto`, `containsFocus` through a slot, the clipboard's focus rule (Edit → Copy at the body, two viewers), shortcuts from text fields, the shell's focus requests, a command's `panel.focus` and `shortcutInTextFields` matching, the hook in each framework (a rise, a late mount, never on a plain open, `select`, one document's request not another's), and Find's and the search panel's commands. plugin-shell 7, plugin-commands 45, web 337, the headless adapters 131/167/157/185, the viewer 343/343, the wrappers 24/23/24/26. API snapshots regenerated; the snippets compile on all 40 headless pages in every framework; docs:check passes on both sites.
