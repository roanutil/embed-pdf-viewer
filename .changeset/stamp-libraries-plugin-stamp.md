A stamp library IS a PDF, in Acrobat's own dialect. Its `/Title` is the library name, its `/Names /Pages` registry lists the stamps as `identifier=label` pairs, its pages are the artwork, and `/PieceInfo` carries only what has no standard home (library id, categories, per-stamp kind and subject override). `importLibraryPdf` reads Acrobat-authored libraries as they are — title, identifiers, and labels — and a plain PDF still becomes one stamp per page. The loose (non-PDF) library kind is gone: every asset is a page, so a raster added with `addAsset` becomes a page carrying the image, and `StampAsset.format` / `StampLibrary.storage` no longer exist. `StampLibrary` gains `locale` (PieceInfo `Locale`, when the library states it) and `StampAsset` gains `label` (picker text, default `/Subj`) beside `name` (the identifier — a standard name like `Approved` or an Acrobat-style `#…` one, minted when omitted); placements write both `/Name` and `/Subj`.

New on the capability: `addAssetFromAnnotations(documentId, pon, refs, input)` turns selected annotations into a vector stamp through the engine's appearance export; `updateAsset(id, { label, subject, categories })` relabels in place (the identifier never changes); `exportLibrary(id)` returns the complete PDF and `onLibraryChanged` fires after every change to it — the two calls persistence needs; `placeAsset(documentId, assetId, placement)` places a stamp by code with the same fit, clamp, name, and subject a click produces; `createLibrary` now resolves to the id asynchronously. The hover ghost is resolution-aware: an armed vector asset renders lazily at the on-screen device pixel width (bucketed and cached), so large stamps stay sharp at any zoom.

Persistence stays outside the plugin and DOM-free: `StampLibraryStore` is the port (implement `list`/`put`/`delete` once for your backend, or use `indexedDbByteStore` from `@embedpdf/web` in the browser), `memoryStampStore()` serves tests and SSR, and `restoreStampLibraries` / `persistStampLibraries` wire a store to a capability. `parseStampKey`, `stampKey`, `customStampName`, `assetIdFor`, and the `/PieceInfo` shape (`stampLibraryPieceInfo`, `stampPieceInfo`, the application names and version) are exported for embedders and build steps that author libraries the plugin reads. Requires an engine that implements `pages.setName` / `pages.removeName`.
