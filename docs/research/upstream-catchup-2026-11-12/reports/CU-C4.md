## Vectors

`vectors/changes/` is new, generated by `src/generate-change-vectors.ts` and replayed by
`crates/epdf-engine/tests/change_ops.rs`. Each case runs its steps against a fresh document and
records every worker request a step sent with the worker's answer (CU-C4-D1). Copy names are masked as
`"<uuid>"` and clock timestamps as `"<now>"` (CU-C4-D3). Two runs are identical
(`CU-C4-changes-run{1,2}.sha`, `deterministic=yes`), and the 33 other groups are untouched.

Every recorded outcome matches its case's covers text. The first run didn't: four copy cases were

the create schema refuses, and copying one radio widget with the group's value names a value only the
other widget has. Both stay as named refusal cases (CU-C4-D4).

## Port

Viewports: `pdfium::Document::{viewport_count_raw, viewport_raw, add_viewport_raw,
remove_viewport_raw}` wrap the raw exports, and a `RawViewport` closes on drop (CU-C4-D6).
`pages.list` reads each page's viewports through them and `page_layout_of` converts them to page
space. `measure.viewports` and the scale write no longer load a page.

`pages.setScale` runs in `document.apply` (`changes/scale.rs`): each page takes the page-space measure
on its own visible box, and the reverse groups pages by the scale and box they had, putting each back
only while it still has the scale the change left. `measure.setScale` answers the new layout too.

Rename: the prepare step no longer refuses a changed `nm`. An update writes `/NM`, removing it for
`null` or `""`, and `assert_new_name_free` checks the new name against the page as earlier ops left
it.

`annotations.copy` (`plan_annotation_copy`, `prepare_annotation_copy`, `write_annotation_copy`) and
`forms.copy` (`plan_form_copy`, `copy_fields`) follow upstream's split. Each plans in page space,
writes through the import's batch with the object numbers given and undoes as an import does. The
change context now carries `BundleLimits`, read from `document.applyChanges`'s `limits` (CU-C4-D10).

Two fixes reach the imports as well. A page-space `rect` or `box` with a negative width is refused
(CU-C4-D8), and a widget placement carries `dashArray` and `checkStyle` (CU-C4-D9).

No public binding changed: `epdf-capi`, uniffi and the platform wrappers are untouched, so CU-C7 has
no rename to carry.

## Known gaps

- No vector copies a stamp's drawing, an attachment's file or a popup, and none refuses a copy past a
  bundle limit: `annotation_base.pdf` has none of them. The Rust code paths exist and are untested by
  vectors.
- Two copies of one attachment count once against `resources` and `bundleBytes` in Rust and twice in
  TS (CU-C4-D11). It only shows at those limits.
- `viewportsVersion`, the layout token and `lacksWhatArrivedIn`'s callers are server-side in upstream.
  `epdf-engine` carries the kinds table but has no manifest or token to pin, so nothing replays them.
- The Rust-core wasm payload must export the 5 raw viewport functions to `epdf-wasm`. That build is
  CU-C7's.
